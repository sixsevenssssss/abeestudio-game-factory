# PLAN — abeeStudio · Инструменты

Пакет `@abeestudio/tools` даёт разработчику игры шесть команд и честный вердикт перед отправкой на площадку.

---

## Команды

### `npm start` — dev-сервер
Node.js http-сервер без зависимостей (только stdlib), раздаёт статику из корня игры.
- Авто-перезагрузка: watch на src/ и assets/, Server-Sent Events в браузер (один JS-сниппет в index.html в dev-режиме, убирается при pack).
- `--mobile` — viewport 390×844, эмуляция тач-событий.
- `--throttle N` — искусственная задержка N мс на каждый ответ (эмуляция медленной сети).
- `--open` — открыть браузер автоматически.
- Порт по умолчанию 3000, `--port N` переопределяет.

### `npm run check` — чек-лист готовности
Запускает все зарегистрированные проверки, печатает отчёт (вердикт первым, детали после),
возвращает код 1 если есть хотя бы один fail.

Три статуса: `ok` / `fail` / `skip` (не проверено: причина).
**Ложного зелёного нет.** Если проверка не выполнялась фактически — она skip, не ok.

Декларативный реестр: новая проверка = одна запись в checks[].

### `npm run pack` — упаковщик
Создаёт `build/<game-id>.zip` из игрового проекта.

Исключает: `tools/`, `.git/`, `node_modules/`, `*.map`, `*.test.js`,
`STATE.md`, `BACKLOG.md`, `LOG.md`, `PLAN.md`.

Отчёт: итоговый вес .zip, разбивка по категориям (assets / audio / scripts / styles / other),
топ-10 тяжёлых файлов. Проверяет что index.html лежит в корне zip.

### `npm test` — тесты без браузера
Запускает `test/**/*.test.js` через Node.js встроенный test runner (`node --test`, v18+).
Если запускается из monorepo — также прогоняет `packages/engine/test/`.

### `npm run shots` — скриншоты
Требует Puppeteer. Если не установлен — честный `skip`.

Снимает menu screen в двух языках (ru / en) и двух ориентациях (portrait / landscape).
Сохраняет в `store/screens/`. Нарезает все размеры площадок из одного баннера через sharp/jimp.

### `npm run sim` — симулятор экономики
Читает `game.config.js` (секция `economy`).
Прогоняет модель на `--hours N` (default 8, max 168), шаг — 15 минут (одна сессия).
Считает накопленные монеты и открытый контент.
ASCII-кривая в терминале (20 строк × 60 колонок).
Детектирует: монеты кончаются через X часов (риск), потолок достигается через Y дней.

## Структура пакета

```
packages/tools/
├── src/
│   ├── serve.js          dev-сервер (entry: node tools/serve.js)
│   ├── check.js          чек-лист (entry: node tools/check.js)
│   ├── pack.js           упаковщик (entry: node tools/pack.js)
│   ├── test.js           тест-раннер (entry: node tools/test.js)
│   ├── shots.js          скриншоты (entry: node tools/shots.js)
│   ├── sim.js            симулятор (entry: node tools/sim.js)
│   └── checks/
│       ├── runner.js     декларативный реестр и runner
│       ├── i18n.js       L-проверки
│       ├── platform.js   P-проверки
│       ├── archive.js    A-проверки
│       ├── magic-numbers.js   M-проверки
│       ├── brand.js      B-проверки
│       ├── ads.js        AD-проверки
│       └── store.js      S-проверки
├── test/
│   └── fixtures/
│       └── minimal-game/  тест-фикстура для статических проверок
├── PLAN.md
├── BACKLOG.md
├── STATE.md
├── LOG.md
└── API.md
```

Скрипты копируются в `tools/` игры генератором (`create-yandex-game`).
Игра запускает их через npm scripts: `"start": "node tools/serve.js"`.

## Критерий готовности

1. На свежесозданном из шаблона проекте все команды отрабатывают без ручной подготовки.
2. `check` ловит каждую намеренно подложенную поломку своего типа и объясняет её человеческим языком.
3. `pack` даёт архив, который открывается как статика и запускается.
4. `API.md` описывает все команды, флаги и коды возврата.

---

## Зависимость от соседних сессий

- Статические проверки (тики 1–12): не зависят от template/, разрабатываются по тест-фикстуре.
- Интеграция с шаблоном (тик 13): разблокируется после engine тик 16 (template/ + i18n).
- Браузерные проверки (тики 14–19): разблокируются после установки Puppeteer.
- Скриншоты и витрина (тики 20–22): разблокируются после браузерных проверок.
