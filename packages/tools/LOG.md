## [2026-08-03] Тик 2 — runner.js + check.js

**Сделано:** инфраструктура чек-листа, 25 тестов, точка входа check.js с автодискаврингом.

**Решения:**
- `runChecks` — последовательный (не параллельный) запуск: детерминированный порядок, проще отлаживать.
- Исключение в fn → `skip`, не `fail`: ошибка в самой проверке не должна давать ложный fail или ложный ok. Три состояния принципиальны.
- `check.js` автоматически загружает все `.js` файлы из `checks/` через dynamic import + pathToFileURL. Добавить новую проверку = добавить файл, без правки check.js.
- `exitCode`: skip ≠ fail. Skip — «не проверено», не блокирует отправку, но честно виден в отчёте. Это намеренное решение: скрыть «нет браузера» за ненулевым кодом — значит либо врать, либо вечно блокировать CI.
- Склонение ruPlural: числа 11–19 обрабатываются отдельно (русское исключение).

**Проверено от противного:**
- Исключение в fn → skip (не fail) ✓
- Неверный статус из fn → skip ✓
- only=несуществующий → пустой массив, exit 0 ✓
- skip → exit 0 (не блокирует) ✓

## [2026-08-03] Внеплановая починка — ложное зелёное при пустом чек-листе

**Поломка:** `check.js` с пустым реестром печатал «✅ ГОТОВО К ОТПРАВКЕ (0 ✔ 0 пропущено)» и возвращал 0. Инструмент, созданный чтобы не пустить непроверенную игру на модерацию, сам выдавал ей зелёное — не проверив ничего. Тот же баг сработал бы позже, когда браузерные проверки массово уходят в skip на машине без Chromium.

**Починка:** четыре вердикта вместо двух. Пустой реестр и «все skip» дают «⚠️ ВЕРДИКТ НЕ ВЫДАН» и код возврата 2. Ноль теперь означает ровно «есть подтверждённые ok и ни одной fail», а не «ошибок не нашлось».

**Причина решения:** ноль — это обещание «проверено, можно заливать». Отдавать его, когда проверок не было, значит врать вызывающему; на этих вердиктах игру отправляют на модерацию, где отказ удваивает кулдаун. «Не знаю» обязано отличаться от «всё хорошо» и в тексте, и в коде возврата.

**Проверено:** 52/52 теста зелёные. Пустой реестр вручную: «ВЕРДИКТ НЕ ВЫДАН», exit 2. Добавлено 6 тестов ровно на этот класс ошибки (пустой реестр, все-skip, ok+skip, fail+skip).

**API.md:** переписаны коды возврата, добавлена таблица вердиктов, статусы команд приведены к правде (готово / каркас / не реализовано) — раньше таблица помечала тиками то, чего нет.

## [2026-08-03] Тик 3 — src/checks/i18n.js (L1–L4)

**Сделано:** первые четыре реальные проверки, `src/checks/util.js` с общими утилитами, фикстура `test/fixtures/i18n-game/`, 24 теста «от противного».

**Решения:**
- Один файл проверок = одна тема, но несколько пунктов: `checks/i18n.js` экспортирует массив из четырёх проверок. Загрузчик в `check.js` расширен: принимает и объект, и массив. Иначе на 22 проверки вышло бы 22 почти пустых файла.
- `util.js` вынесен сразу: обход файлов, поиск папки словарей, разворачивание вложенного JSON в точечные пути, токенизация строковых литералов. Тики 4–9 будут переиспользовать это, а не копировать.
- Токенизация L3 — конечный автомат, не regex. Наивный regex ломается на апострофе внутри комментария и на слэше внутри строки; для проверки, которая обвиняет разработчика в непереведённом тексте, точность важнее краткости.
- L3 сканирует только `src/game/`, `src/screens/`, `src/scenes/`. `engine/`, `ui/`, `platform/` приходят из пакетов и не являются зоной ответственности игры — ругать за них бессмысленно.
- L2 при отсутствии словарей даёт `skip`, а не `ok` и не `fail`: сама проверка не выполнялась, дублировать вердикт L1 нечестно.
- Кириллица никогда не считается технической строкой. Лучше разобрать один спорный случай руками, чем пропустить нелокализованную подпись в релиз.

**Поломка и починка (внутри тика):**
- Первый же прогон на здоровой фикстуре дал ложное красное: `'16px sans-serif'` определилось как текст для игрока — есть пробел и два латинских слова.
- Починено: в фильтр технических строк добавлены CSS-размеры, generic-семейства шрифтов, `rgba()/translate()/calc()`. Ложное красное так же вредно, как ложное зелёное: оно учит людей игнорировать инструмент. Отдельный тест-регрессия с реалистичным набором CSS, селекторов и имён событий.

**Проверено от противного (главное требование тика):**
- Каждая из четырёх поломок ловится своей проверкой и называет место: пропавший ключ по имени, пустое значение по ключу, зашитый текст с `файл:строка`, отсутствующий экран языка с подсказкой куда положить.
- Четыре поломки одновременно → ровно четыре fail, без перекрёстных срабатываний.
- Проверено и обратное: `L10n.t(...)`, комментарии, `console.warn`, CSS-значения и код в `src/engine/` ложных красных не дают.
- Отчёт на сломанном проекте прочитан глазами: вердикт первой строкой, дальше место и объяснение.

**Замечено попутно:** `node --test test/` в Node 24 не работает — папка трактуется как путь к модулю. Нужен glob. Записано в STATE.md для тика 11, чтобы `npm test` не родился сломанным.
