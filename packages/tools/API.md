# API — @abeestudio/tools

Публичный API пакета `@abeestudio/tools`. Версия: 0.0.0 (в разработке).

---

## Команды

| Команда | Статус | Описание |
|---|---|---|
| `npm start` | ✅ готово | Dev-сервер со статикой и авто-перезагрузкой |
| `npm run check` | 🔧 13 проверок из 22 (A1–A4, L1–L4, M1, P1–P4) | Полный чек-лист готовности |
| `npm run pack` | ⬜ тик 10 | Упаковка zip для площадки |
| `npm test` | ⬜ тик 11 | Прогон тестов без браузера |
| `npm run sim` | ⬜ тик 12 | Симулятор экономики |
| `npm run shots` | ⬜ тик 20 | Скриншоты для карточки (требует Puppeteer) |

## npm start

```
node tools/serve.js [gameDir] [options]

gameDir        Путь к игре (default: текущая директория)
--port N       Порт (default: 3000)
--mobile       Viewport 390×844, эмуляция тача
--throttle N   Задержка ответа N мс (эмуляция медленной сети)
--open         Открыть браузер автоматически
```

Выходные коды: 0 — штатный запуск, 1 — порт занят или директория не найдена.

## npm run check

```
node tools/check.js [gameDir] [options]

gameDir        Путь к игре (default: текущая директория)
--only=id      Запустить только одну проверку по id
--json         Вывод в JSON вместо текста
```

**Коды возврата:**
- `0` — есть подтверждённые `ok` и ни одной `fail` (часть проверок могла быть пропущена)
- `1` — есть хотя бы одна `fail`
- `2` — **вердикт не выдан**: реестр проверок пуст или ни одна проверка не выполнилась

Код `2` принципиален. Ноль означает «проверено и можно заливать». Если проверок не было
вовсе или все они пропустились, вернуть ноль — значит соврать и CI, и человеку.
«Не знаю» обязано отличаться от «всё хорошо»: отказ модерации удваивает кулдаун.

**Статусы проверок:**
- `ok` — проверено, в порядке
- `fail` — проверено, найдена проблема (сообщение + где чинить)
- `skip` — **не проверено** (указана причина: нет браузера / нет зависимости / требует ручной проверки)

Проверка, которая упала с исключением, становится `skip`, а не `fail` и не `ok`:
сломанный инструмент не имеет права ни обвинять игру, ни выдавать ей зелёное.

**Вердикты:**

| Условие | Заголовок | Код |
|---|---|---|
| Есть `ok`, нет `fail` | ✅ ГОТОВО К ОТПРАВКЕ | 0 |
| Есть `fail` | ❌ НЕ ГОТОВО — N проблем | 1 |
| Реестр пуст | ⚠️ ВЕРДИКТ НЕ ВЫДАН — ни одна проверка не зарегистрирована | 2 |
| Все `skip` | ⚠️ ВЕРДИКТ НЕ ВЫДАН — ни одна проверка не выполнилась | 2 |

**Формат отчёта:**

```
✅  ГОТОВО К ОТПРАВКЕ  (12 ✔  3 пропущено)

✅  L1     Ключи i18n совпадают
❌  L3     Строки вне L10n.t
         src/game/scenes/gameplay.js:34 — "Score: "
         → Где исправить: src/game/scenes/gameplay.js, строка 34
⬜  N1     Сетевые запросы
         Не проверено: нет браузера
```

Результат может содержать `show: true` — тогда сообщение печатается и при зелёном
статусе. Нужно измерительным проверкам вроде `A3`, где измеренное число и есть
смысл проверки.

`A4` возвращает `skip` всегда и намеренно: пункт есть в чек-листе студии, но без
браузера не измеряется. Скрыть его — значит дать прочитать зелёный отчёт как
«время загрузки проверено».

`A3` меряет РАСПАКОВАННЫЙ вес папки. Вес zip меньше и меряется командой `pack`.
`fail` только при превышении лимита площадки (100 МБ); цели студии (150 КБ,
8 МБ Poki, 20 МБ CrazyGames) печатаются справкой и вердикта не меняют.

**Реестр проверок.** `check.js` автоматически загружает все `.js` из `src/checks/`
кроме `runner.js` и `util.js`. Файл экспортирует `default` — либо одну проверку
`{ id, title, fn }`, либо массив проверок, когда одна тема даёт несколько пунктов.
`fn(gameDir) → { status, message, fix? }`. Добавление проверки = добавление файла,
правка `check.js` не нужна.

### Реализованные проверки

| ID | Что проверяет | Когда `skip` |
|---|---|---|
| `A1` | `index.html` лежит в корне | папки нет |
| `A2` | Имена файлов без пробелов и не-ASCII | файлов нет |
| `A3` | Распакованный вес + топ-5 тяжёлых (измерение) | нечего измерять |
| `A4` | Время до первого кадра | **всегда**: нужен браузер |
| `L1` | Ключи `ru.json` и `en.json` совпадают один в один | никогда: нет словарей → `fail` |
| `L2` | В словарях нет пустых значений (`""`, пробелы, `null`) | словари не читаются (см. L1) |
| `L3` | В коде игры нет строк текста вне `L10n.t` | нет `src/game/`, `src/screens/`, `src/scenes/` |
| `L4` | Экран выбора языка присутствует | нет папки `src/` |
| `M1` | Нет магических чисел в логике игры | нет кода игры вне `data/` |
| `P1` | Нет обращений к `ysdk` / `YaGames` вне `src/platform/` | нет кода игры |
| `P2` | Нет `localStorage` / `sessionStorage` мимо `Save` | нет кода игры |
| `P3` | Нет внешних адресов в коде и разметке (п. 8.4) | нет кода игры и `index.html` |
| `P4` | Нет `WebSocket` / `EventSource` / `sendBeacon` / `XHR` | нет кода игры |

`M1` считает магическими все числа кроме `0, 1, -1, 2, -2, 0.5, 100, 1000`.
`src/game/data/` не проверяется — числам там место. Не считаются: индексы массивов,
hex-литералы, части идентификаторов, числа в строках и комментариях. Порог `fail` —
5 РАЗНЫХ значений; ниже порога возвращается `ok` c `show: true`, то есть числа
перечислены в отчёте, но отправку не блокируют.

`P3` и `P4` — статические: видят литералы в коде и разметке. Адрес, собранный
в рантайме из частей, ловит только браузерная `N1` (тик 15, не реализована).
Зелёное `P3` не означает «сеть проверена целиком».

Разрешены и не считаются поломкой: `ysdk` внутри `src/platform/`, тег SDK площадки
в `index.html` (обязателен, п. 1.1), пространства имён `w3.org` в SVG, `localhost`.

`L3` сканирует только код игры. `src/engine/`, `src/ui/`, `src/platform/` приходят
из пакетов и не проверяются. Не считаются текстом для игрока: аргументы `L10n.t`,
комментарии, `console.*`, пути модулей, селекторы, имена событий, значения CSS.
Кириллица технической строкой не считается никогда.

### Запланированные проверки

B1–B3 (бренд), AD1–AD2 (реклама), S1–S3 (карточка) — статические, тики 7–9.
N1 (сеть), C1 (консоль), AD2r (пауза на рекламе), V1 (видимость), SV1–SV2 (сохранения)
— требуют браузера, тики 15–19. Пока не реализованы.

## Подключение в игру

Скрипты копируются в `tools/` игрового проекта генератором `create-yandex-game`.
Игровой `package.json`:

```json
{
  "scripts": {
    "start":  "node tools/serve.js",
    "check":  "node tools/check.js",
    "pack":   "node tools/pack.js",
    "test":   "node tools/test.js",
    "shots":  "node tools/shots.js",
    "sim":    "node tools/sim.js"
  }
}
```
